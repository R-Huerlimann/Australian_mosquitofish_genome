04 — Repeat Annotation
================

This section describes the repeat annotation pipeline used for the
*Gambusia holbrooki* genome. The approach follows a multi-round strategy
adapted from [Daren Card’s genome repeat annotation
workflow](https://darencard.net/blog/2022-07-09-genome-repeat-annotation/),
combining *de novo* repeat modelling with iterative classification and
masking.

All steps were run on the OIST Deigo HPC cluster using a RepeatModeler2
Singularity container.

------------------------------------------------------------------------

## Inputs

| File | Description |
|----|----|
| gamhol_genome_hap1_final_clnd.fa | HAP1 scaffolded assembly (cleaned) |
| dfam39/ | Dfam 3.9 database partitions (Vertebrata/Otomorpha) |

## Part 1 — De Novo Repeat Modelling

### Step 1.1 — Build Database and Run RepeatModeler

Build a RepeatModeler database from the assembly and run de novo repeat
identification with LTR structural detection enabled.

``` bash
# Build database (only needs to run once)
BuildDatabase -name gamhol gamhol_genome_hap1_final_clnd.fa

# Run RepeatModeler
RepeatModeler -threads 40 \
              -LTRStruct \
              -database gamhol \
              -recoverDir RM_3068045.ThuApr161805502026
```

> **Resources:** 40 CPUs, 400 GB RAM, 20-day wall time (`largemem`
> partition).

**Notes:** - `-LTRStruct` enables the structural LTR retrotransposon
discovery pipeline (LTRharvest + LTR_retriever), which identifies LTR
elements by their structural features rather than sequence similarity
alone. This substantially improves LTR element detection and is
recommended for all vertebrate genomes. - RepeatModeler is the most
resource-intensive step in the pipeline. The 20-day wall time reflects a
real run on a ~676 Mb genome; the job may complete sooner depending on
repeat content. - `-recoverDir` resumes from a previous interrupted run.
On the first run, omit this flag. The recovery directory name is
automatically generated by RepeatModeler. - Output is a repeat family
library (`gamhol-families.fa`) containing de novo repeat consensus
sequences classified where possible.

------------------------------------------------------------------------

### Step 1.2 — Classify Unknown Repeats — Round 1

Add a species prefix to all repeat families, split into known and
unknown subsets, and attempt classification of unknowns using Repbase
*Gambusia* entries and self-hits.

``` bash
# Add species prefix and split into known/unknown
cat gamhol-families.fa \
    | seqkit fx2tab \
    | awk '{ print "Gamhol_"$0 }' \
    | seqkit tab2fx \
    > gamhol-families.prefix.fa

cat gamhol-families.prefix.fa | seqkit fx2tab | grep -v "Unknown" | seqkit tab2fx \
    > gamhol-families.prefix.fa.known

cat gamhol-families.prefix.fa | seqkit fx2tab | grep "Unknown" | seqkit tab2fx \
    > gamhol-families.prefix.fa.unknown

# Classify unknowns against Gambusia Repbase entries and self library
repclassifier -t 6 \
    -d Gambusia \
    -u gamhol-families.prefix.fa.unknown \
    -k gamhol-families.prefix.fa.known \
    -a gamhol-families.prefix.fa.known \
    -o round-1_RepbaseGambusia-Self
```

> **Resources:** 6 CPUs, 50 GB RAM, 12-hour wall time.

**Notes:** - Adding a species prefix (`Gamhol_`) to all repeat family
names avoids naming conflicts when combining with Dfam/Repbase library
entries downstream. - RepeatModeler classifies many families
automatically, but a substantial proportion remain labelled `Unknown`.
These are the target of the iterative `repclassifier` steps. -
`repclassifier` attempts to assign unknown repeat families a
classification by aligning them against a known library (`-k`) and a
reference database (`-d Gambusia`). The `-a` flag provides an additional
alignment reference; here we use the known library as both reference and
anchor. - Using `-d Gambusia` leverages any *Gambusia*-specific entries
in the Dfam/Repbase database as classification anchors. For species with
few close relatives in the database, this step may classify only a small
proportion of unknowns.

------------------------------------------------------------------------

### Step 1.3 — Classify Unknown Repeats — Round 2

Re-run `repclassifier` on remaining unknowns from round 1, now using the
round 1 known library as the sole reference (self-classification).

``` bash
repclassifier -t 12 \
    -u round-1_RepbaseGambusia-Self/round-1_RepbaseGambusia-Self.unknown \
    -k round-1_RepbaseGambusia-Self/round-1_RepbaseGambusia-Self.known \
    -a round-1_RepbaseGambusia-Self/round-1_RepbaseGambusia-Self.known \
    -o round-2_Self
```

> **Resources:** 12 CPUs, 50 GB RAM, 1-hour wall time.

**Notes:** - Round 2 uses only the self-classified known library from
round 1, without the Repbase `-d` database. This allows repeat families
that were classified in round 1 to inform classification of remaining
unknowns through similarity. - Additional rounds can be run until the
number of unknowns plateaus. Here two rounds were sufficient. - The
final outputs `round-2_Self.known` and `round-2_Self.unknown` are used
as custom repeat libraries in the RepeatMasker steps.

------------------------------------------------------------------------

## Part 2 — Repeat Masking

The four-round RepeatMasker strategy masks repeat classes sequentially,
with each round taking the softmasked output of the previous round as
input. This approach avoids cross-contamination between repeat classes
and follows the strategy described in [Daren Card’s
workflow](https://darencard.net/blog/2022-07-09-genome-repeat-annotation/).

### Step 2.1 — Mask Simple Repeats

``` bash
RepeatMasker -pa 32 \
             -a \
             -e ncbi \
             -dir 01_simple_out \
             -noint \
             -xsmall \
             gamhol_genome_hap1_final_clnd.fa

# Rename outputs
rename .fa.masked .simple_mask.masked 01_simple_out/gamhol_genome_hap1_final_clnd.fa*
rename .masked .masked.fasta 01_simple_out/gamhol_genome_hap1_final_clnd.fa*
```

> **Resources:** 32 CPUs, 120 GB RAM, 20-hour wall time.

**Notes:** - `-noint` restricts masking to simple/low-complexity repeats
only (satellites, simple repeats, low-complexity regions), excluding
interspersed elements. This keeps the rounds cleanly separated. -
`-xsmall` softmasks (lowercase) rather than hardmasks (N). Softmasking
is preferred as it preserves sequence information and is compatible with
most downstream annotation tools. - `-e ncbi` uses the NCBI/BLAST search
engine rather than cross_match.

------------------------------------------------------------------------

### Step 2.2 — Mask Gambusia Elements from Dfam

``` bash
RepeatMasker -pa 64 \
             -a \
             -e ncbi \
             -dir 02_gambusia_out \
             -nolow \
             -species Gambusia \
             01_simple_out/gamhol_genome_hap1_final_clnd.simple_mask.masked.fasta
```

> **Resources:** 64 CPUs, 500 GB RAM, 100-hour wall time.

**Notes:** - `-species Gambusia` queries the Dfam 3.9 database for
*Gambusia*-specific and ancestral repeat entries. The local Dfam
partition (`dfam39/`) covering Vertebrata and Otomorpha was used rather
than the default bundled library, which provides much broader taxonomic
coverage. - `-nolow` skips simple/low-complexity repeats since these
were already handled in round 1. - This step is the most
resource-intensive masking round due to the size of the Dfam search
space. - Input is the softmasked output from round 1.

------------------------------------------------------------------------

### Step 2.3 — Mask Known De Novo Repeats

``` bash
RepeatMasker -pa 32 \
             -a \
             -e ncbi \
             -dir 03_known_out \
             -nolow \
             -lib round-2_Self/round-2_Self.known \
             02_gambusia_out/gamhol_genome_hap1_final_clnd.gambusia_mask.masked.fasta
```

> **Resources:** 32 CPUs, 120 GB RAM, 72-hour wall time.

**Notes:** - `-lib` supplies the custom de novo repeat library (known
families from round 2 of `repclassifier`) rather than a database
species. This targets species-specific repeats that may not be
represented in Dfam. - Input is the output from round 2.

------------------------------------------------------------------------

### Step 2.4 — Mask Unknown De Novo Repeats

``` bash
RepeatMasker -pa 32 \
             -a \
             -e ncbi \
             -dir 04_unknown_out \
             -nolow \
             -lib round-2_Self/round-2_Self.unknown \
             03_known_out/gamhol_genome_hap1_final_clnd.known_mask.masked.fasta
```

> **Resources:** 32 CPUs, 120 GB RAM, 2-hour wall time.

**Notes:** - This round uses the unclassified repeat families as the
library. Although these elements have no assigned classification,
masking them ensures complete repeat coverage in the final masked
genome. - The short wall time reflects the relatively small proportion
of genome covered by unclassified repeats after the previous three
rounds.

------------------------------------------------------------------------

### Step 2.5 — Post-Processing: Combine and Summarise

Merge outputs from all four masking rounds into a single combined set of
annotation files, generate a summary table of repeat content, and
convert to GFF3 format.

``` bash
# Combine .cat.gz files from all rounds
cat 01_simple_out/gamhol_genome_hap1_final_clnd.fa.cat.gz \
    02_gambusia_out/gamhol_genome_hap1_final_clnd.gambusia_mask.cat.gz \
    03_known_out/gamhol_genome_hap1_final_clnd.gambusia_mask.masked.fasta.fasta.cat.gz \
    04_unknown_out/gamhol_genome_hap1_final_clnd.known_mask.masked.fasta.fasta.cat.gz \
    > 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.cat.gz

# Combine .out files (skip header lines from rounds 2-4)
cat 01_simple_out/gamhol_genome_hap1_final_clnd.fa.out \
    <(tail -n +4 02_gambusia_out/gamhol_genome_hap1_final_clnd.gambusia_mask.out) \
    <(tail -n +4 03_known_out/gamhol_genome_hap1_final_clnd.gambusia_mask.masked.fasta.fasta.out) \
    <(tail -n +4 04_unknown_out/gamhol_genome_hap1_final_clnd.known_mask.masked.fasta.fasta.out) \
    > 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.out

# Combine .align files
cat 01_simple_out/gamhol_genome_hap1_final_clnd.fa.align \
    02_gambusia_out/gamhol_genome_hap1_final_clnd.gambusia_mask.align \
    03_known_out/gamhol_genome_hap1_final_clnd.gambusia_mask.masked.fasta.fasta.align \
    04_unknown_out/gamhol_genome_hap1_final_clnd.known_mask.masked.fasta.fasta.align \
    > 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.align

# Re-summarise combined results with ProcessRepeats
ProcessRepeats -a \
               -species Gambusia \
               05_full_out/gamhol_genome_hap1_final_clnd.full_mask.cat.gz

# Calculate genome and N lengths
allLen=$(seqtk comp gamhol_genome_hap1_final_clnd.fa | datamash sum 2)
nLen=$(seqtk comp gamhol_genome_hap1_final_clnd.fa | datamash sum 9)
echo "Genome length: ${allLen}"
echo "N bases: ${nLen}"

# Tabulate repeat content per subfamily as fraction of genome
cat 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.out \
    | tail -n +4 \
    | awk -v OFS="\t" '{ print $6, $7, $11 }' \
    | awk -F'[\t/]' -v OFS="\t" '{ if (NF==3) print $3,"NA",$2-$1+1; else print $3,$4,$2-$1+1 }' \
    | datamash -sg 1,2 sum 3 \
    | grep -v "\?" \
    | awk -v OFS="\t" -v genomeLen="${allLen}" '{ print $0, $3/genomeLen }' \
    > 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.table

# Convert .out files to GFF3
rmOutToGFF3custom -o 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.out \
    > 05_full_out/gamhol_genome_hap1_final_clnd.full_mask.gff3
rmOutToGFF3custom -o 05_full_out/gamhol_genome_hap1_final_clnd.simple_mask.out \
    > 05_full_out/gamhol_genome_hap1_final_clnd.simple_mask.gff3
rmOutToGFF3custom -o 05_full_out/gamhol_genome_hap1_final_clnd.complex_mask.out \
    > 05_full_out/gamhol_genome_hap1_final_clnd.complex_mask.gff3
```

> **Resources:** 16 CPUs, 50 GB RAM, 12-hour wall time.

**Notes:** - The `.out` files from rounds 2–4 have a 3-line header that
must be stripped (`tail -n +4`) before concatenation to avoid corrupting
the merged file. - `ProcessRepeats` re-runs the RepeatMasker
summarisation step on the combined `.cat.gz` file to produce a single
accurate repeat content summary (`.tbl`) for the whole genome. Without
this step the per-round summaries would not be directly additive. - The
repeat content table (`.table`) gives the fraction of the genome
occupied by each repeat subfamily — this is the source for downstream
repeat composition figures. - `rmOutToGFF3custom` is a utility script
from Daren Card’s pipeline that converts the RepeatMasker `.out` format
to GFF3. Three GFF3 files are produced: full (all repeats), simple only,
and complex/interspersed only. The complex GFF3 is used to hardmask the
genome for gene annotation in the next step.

## Outputs

| File | Description |
|----|----|
| `gamhol-families.prefix.fa` | De novo repeat library with species prefix |
| `round-2_Self.known` | Classified de novo repeat families |

The complex repeat GFF3 and the final softmasked FASTA are passed to
**[05 — functional annotation](05_functional_annotation.md)**.
